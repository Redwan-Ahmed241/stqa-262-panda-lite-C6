## 3. Defect Reports

Below are the bugs we found during testing. Each one was verified to be reproducible.

### Defect 1: System accepts passwords shorter than 6 characters
- **ID:** `597a51`
- **Found by:** Showket (`0112310043`)
- **Severity:** High
- **Steps to Reproduce:**
  1. Send `POST /auth/register` with `{"name": "Test", "email": "short@test.com", "password": "12345", "role": "customer"}`
- **Expected:** 400 Bad Request — password should be rejected since it's under 6 characters
- **Actual:** 201 Created — the user gets registered with a 5-character password
- **Test Case:** `597a51`

### Defect 2: Any user can update any restaurant (no ownership check)
- **ID:** `248301`
- **Found by:** Showket (`0112310043`)
- **Severity:** Critical
- **Steps to Reproduce:**
  1. Login as restaurant owner Bob and create a restaurant.
  2. Login as a different restaurant owner Charlie.
  3. Send `PATCH /restaurants/<bob_restaurant_id>` with `{"name": "Changed"}` using Charlie's token.
- **Expected:** 403 Forbidden — only the owner should be able to update their restaurant
- **Actual:** 200 OK — the restaurant name gets changed by someone who doesn't own it
- **Test Case:** `248301`

### Defect 3: Server crashes with 500 error on invalid numerical inputs
- **ID:** `63a9e3`
- **Found by:** Siratul (`0112231070`)
- **Severity:** Medium
- **Steps to Reproduce:**
  1. Login as restaurant owner Bob.
  2. Send `PATCH /menu-items/<item_id>` with `{"price": -10}`.
- **Expected:** 400 Bad Request with a proper error message
- **Actual:** 500 Internal Server Error — the server crashes instead of handling it properly
- **Note:** The same pattern happens with rating scores outside 1–5 (see test `fa5795`)
- **Test Case:** `63a9e3`

### Defect 4: Restaurant owners and riders can place orders
- **ID:** `3908f2`
- **Found by:** Siratul (`0112231070`)
- **Severity:** High
- **Steps to Reproduce:**
  1. Login as restaurant owner Bob.
  2. Send `POST /orders` with a valid restaurant and items.
- **Expected:** 403 Forbidden — only customers should be able to order
- **Actual:** 201 Created — the order goes through even though Bob is a restaurant owner
- **Test Case:** `3908f2`

### Defect 5: Orders can be placed to closed restaurants
- **ID:** `ed8288`
- **Found by:** Siratul (`0112231070`)
- **Severity:** High
- **Steps to Reproduce:**
  1. Close a restaurant with `PATCH /restaurants/<id>` setting `isOpen: false`.
  2. As a customer, send `POST /orders` targeting that closed restaurant.
- **Expected:** 400 Bad Request — "Restaurant is currently closed"
- **Actual:** 201 Created — order is accepted even though the restaurant is closed
- **Test Case:** `ed8288`

### Defect 6: Customer password hash shows up in order response
- **ID:** `d06490`
- **Found by:** Siratul (`0112231070`)
- **Severity:** Critical
- **Steps to Reproduce:**
  1. As a customer, place an order via `POST /orders`.
  2. Look at the response body — check the `customer` field inside the response.
- **Expected:** Response should not contain any password data
- **Actual:** The response includes `"passwordHash": "$2b$10$..."` — the hashed password is visible to anyone reading the response
- **Test Case:** `d06490`

### Defect 7: Platform fee calculated on the wrong amount
- **ID:** `d06491`
- **Found by:** Siratul (`0112231070`)
- **Severity:** High
- **Steps to Reproduce:**
  1. Place an order where subtotal = 570 and delivery fee = 50.
  2. Check the `platformFee` field in the response.
- **Expected:** Platform fee = 10% of subtotal = 57. Total should be 570 + 50 + 57 = 677
- **Actual:** Platform fee = 62, Total = 682. The fee is calculated as 10% of (subtotal + delivery fee) instead of just subtotal
- **Test Case:** `d06490` (found in the same order response)

### Defect 8: Order lifecycle doesn't enforce proper rules
- **ID:** `66d2ac`, `0e3a14`, `ee3af5`
- **Found by:** Redwan (`011221241`)
- **Severity:** High
- **Steps to Reproduce:**
  1. **Wrong cancellation fee:** Accept an order, then cancel it. The fee should be 50 but comes back as 36.
  2. **Status skipping:** Place a new order and try to jump from "placed" directly to "preparing" (skipping "accepted").
  3. **Cancel during preparation:** Advance an order to "preparing" and try to cancel it.
- **Expected:** Cancellation fee = 50. Skipping steps should return 400. Cancelling during preparation should return 400.
- **Actual:** Fee is 36 instead of 50. Status jumps from "placed" to "preparing" (200 OK). Cancellation works during "preparing" (200 OK).
- **Test Cases:** `66d2ac`, `0e3a14`, `ee3af5`

### Defect 9: Missing permission checks on order operations
- **ID:** `cf3377`, `afd0d8`, `af190e`
- **Found by:** Redwan (`011221241`)
- **Severity:** Critical
- **Steps to Reproduce:**
  1. **Double claiming:** Rider Dave claims an order. Rider Eve tries to claim the same order.
  2. **Unauthorized status change:** Eve (not the assigned rider) tries to mark the order as "picked_up".
  3. **Viewing others' orders:** Customer Frank tries to view an order that belongs to Alice.
- **Expected:** Second claim → 409 Conflict. Unauthorized status change → 403 Forbidden. Viewing others' order → 403 Forbidden.
- **Actual:** All three return 200 OK — the server doesn't check who is making the request
- **Test Cases:** `cf3377`, `4a70ec`, `af190e`

### Defect 10: Rating system accepts invalid scores and allows duplicates
- **ID:** `fa5795`, `7fb0aa`
- **Found by:** Redwan (`011221241`)
- **Severity:** Medium
- **Steps to Reproduce:**
  1. **Invalid score:** Rate a delivered order with score = 6 via `POST /orders/<id>/rate`.
  2. **Duplicate:** Rate a restaurant on a delivered order, then send the exact same rating again.
- **Expected:** Score outside 1–5 → 400 Bad Request. Duplicate rating → 409 Conflict.
- **Actual:** Score 6 causes 500 Internal Server Error (server crash). Duplicate rating returns 201 Created (allows multiple ratings for the same thing).
- **Test Cases:** `fa5795`, `7fb0aa`
